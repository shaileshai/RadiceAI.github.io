Accessibility

Built to be read by anything.

We sell to public bodies, which means this statement is not decoration. Here is what the site does, what it is measured against, and what we know still falls short.

Standard

WCAG 2.2 AA, self-assessed.

We target WCAG 2.2 level AA, which is the technical basis of EN 301 549 and of the European Accessibility Act. We believe the site substantially conforms.

It has not been independently audited. That sentence is the honest status and it stays here until an audit exists, at which point this page will name who did it and when. Parts of the assessment are mechanical — contrast is measured on every element of every page by a script that fails the build — but a machine cannot tell you whether a page makes sense to someone using a screen reader. That part is still just us.

What is done

Keyboard first, motion optional.

The site is a set of static documents with progressive enhancement on top. Turn off JavaScript and every page still renders, navigates and reads correctly — including the nav panels, which open on focus in CSS alone.

Keyboard

Every control is reachable and operable by keyboard in a logical order, and focus is visible. The nav panels open on focus, so their links are reachable without a pointer.

Reduced motion

With prefers-reduced-motion set, the animated object is removed entirely, scroll reveals are off, and page transitions become ordinary page loads. No content depends on motion.

Without JavaScript

All eleven pages are plain HTML documents. Navigation, the nav panels and the whole of the text work with scripting disabled.

Structure

One h1 per page, headings in order, real landmarks, and lists that are lists. The decorative object is a canvas marked aria-hidden and carries no information.

Contrast, measured

Every text element on every page is measured against its computed background by a script in the repository, and the build is not published while anything reads below AA. That found and fixed eleven real shortfalls, including our own accent blue. Text is never an image.

Zoom

Readable at 200% zoom and at 320 CSS pixels wide. Nothing is pinned to a fixed pixel height that clips when text grows.

Known shortfalls

The list we have not finished.

A statement that claims no problems is a statement nobody checked. These are the ones we know about, and each is a real item of work rather than a disclaimer.

Nav panels on hover

The panels open on hover as well as focus. On some touch and switch-access setups the hover state is awkward. Every link inside them also appears in the footer, which is plain and always visible.

The mobile menu needs JavaScript

On a narrow screen with scripting off, the menu button does nothing and navigation falls to the footer. It works, but it is worse than it should be.

The object costs power

The WebGL object on the opening screen is decorative and hidden from assistive technology, but it still uses the GPU. It is removed under reduced-motion; it is not yet removed under a low-power hint.

No audit, no formal testing report

Screen reader testing has been done by us, not by daily users of one. That is a gap we can only close by paying somebody who knows more than we do.

Report a barrier

Tell us what stopped you.

Write to privacy@radice.ai with the page, what you were trying to do, and what got in the way. We will acknowledge within five working days and tell you either when it is fixed or why it is hard.

If you need something on this site in another format, ask and we will send it. This statement was last reviewed in August 2026.
